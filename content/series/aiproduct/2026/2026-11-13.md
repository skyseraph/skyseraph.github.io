## 需求雷达

### 需求 1：Agent 通信身份认证——打电话的到底是谁

**痛点**：Muse 通话上线与 United 全面封禁 AI 订票同日发生（均见上），接听端没有标准手段区分「本人 / 持委托的 agent / 骚扰 AI」，而人声伪装的军备竞赛让「听出是 AI」越来越不可行。
**场景**：若 2027 年美国商家客服来电有 10% 由 AI 代拨，每月就是千万级需要「亮明身份」的握手时刻，接听方缺的是接入即用的核验端点。
**机会**：面向企业 PBX / 云呼叫中心的「agent 呼入认证 SaaS」：核验呼叫方 AI 的委托凭证（谁授权、范围、可撤销），给接线员绿黄红分级。差异点：现有反骚扰方案只识别「是不是 AI」，没人做「这个 agent 有没有权限」。

### 需求 2：Agent 流量的预算熔断——别让 54% 的空转烧钱

**痛点**：[Termination Lag](https://arxiv.org/abs/2611.14960) 实测 agent 在已解出正确补丁后仍消耗 35–60% 的步骤，1–8% 的运行甚至把对的改回错的；叠加 Muse 把真实世界动作纳入 token 计费，多 agent 团队没有任何一层能看到「钱花在哪次徒劳验证上」。
**场景**：10 人团队跑 30 个并行 agent、月烧 $3–5K API 费，按论文口径约四成是「解出之后的空转」——对 CFO 是每月上千美元的可压缩盲区。
**机会**：agent 编排层的成本治理中间件：按任务追踪 token 流向，检测「解出后持续调用」模式并自动熔断或降级到便宜模型做验证。差异点：现有 observability 工具只记账不干预，这里要做可执行的预算闸门。

## 产品创意

### 创意 1：AgentSeal — 面向企业的 AI 呼入身份核验端点

- **MVP**（6 周）：可嵌入 Twilio/Vonage 流程的 API：AI 呼入方出示签名委托凭证（发证方、委托人、时效、权限范围），返回通过/拒绝/人工转接三态；只做语音链路身份层，不做对话内容风控。
- **定价锚点**：按核验次数 $0.02–0.05/次，对标每次误判损失的人工工时（3–5 分钟/次）；不对标语音 API 的按分钟计费——身份核验是一次握手，不是一通电话。

### 创意 2：TokenStop — 编排层的预算熔断器

- **MVP**（4 周）：开源一个插在 agent 框架与模型 API 之间的代理层：按 run 聚合 token 消耗，内置「解出后持续活动」的启发式检测（连续 N 步无 diff 产出即告警/暂停），配最简 dashboard 看「有效 vs 空转」比例；不做模型路由、不做评测。
- **定价锚点**：托管版收团队 API 月账单的 10%（省下论文口径 35–60% 空转的一部分即回本）；不对标 observability 全家桶的席位费——这是省钱的分成，不是多一个观察工具。
