## 需求雷达

### 需求 1：agent 凭据的「开放吧台」悖论

**痛点**：[ExtraOrbital](https://www.producthunt.com/products/extraorbital-deleted-1365752) 的定位是「给 agent 开放的数据库、存储与 AI 密钥」——agent 要干活就得拿凭据，凭据一给就是全局风险；同日 [1Password 安全体事件在 HN 拿下 1502 分](https://news.ycombinator.com/item?id=50644817)，证明连专业凭据管理器都守不住单点。
**场景**：10 人团队给编码 agent 配生产库只读凭据，一次间接注入后凭据外泄——需要的是任务级、可撤销、可审计的凭据代理，而现状是「把密钥贴进环境变量」。
**机会**：面向中小团队的 agent 凭据保险箱：凭据永不进 agent 上下文、代理层代为执行、事后全量审计。[NEXUS 的「只改批准的」](https://www.producthunt.com/products/nexus-42)已在验证权限粒度需求。

### 需求 2：网站的「agent 视角」审计

**痛点**：[Bifura](https://www.producthunt.com/products/bifura) 把「看你的网站在 agent 眼里的样子」做成产品——agent 能逛店、能下单之后（[Walmart 黑五进 Muse 已验证渠道](https://techcrunch.com/2026/11/24/walmart-teams-up-with-meta-to-bring-black-friday-deals-to-ai-agent-muse/)），站方对「agent 读到什么」处于盲区。
**场景**：电商站三成请求来自 agent 抓取，但没人知道 agent 提取到的价格、库存、退货政策是什么——结构化数据的错漏在 agent 侧被放大成错误成交。
**机会**：SEO 审计的 agent 版：按「agent 可解析度」而非搜索排名出月度报告，买方是电商与内容站的增长团队。

## 产品创意

### 创意 1：AgentVault — agent 凭据代理层

- **MVP**（4 周）：本地代理进程接管三类凭据（数据库、HTTP、API key），agent 通过 localhost 协议申请操作、凭据不进上下文，全操作留审计日志。明确不做云端版、不做多租户——先把单团队信任链跑通。
- **定价锚点**：对标一次凭据外泄的处置成本（取证+轮换+告知，万美元级）与团队密码管理器的席位价量级；不对标 API 网关——那是流量问题，这是信任问题。

### 创意 2：AgentLens — 网站的 agent 视角月报

- **MVP**（2 周）：用主流模型的 web reader 模式抓取目标站点，输出「agent 可解析度」评分与关键实体（价格/库存/政策）的提取比对，差异即工单。明确不做 SEO 排名、不做爬虫代理。
- **定价锚点**：对标 SEO 审计工具的入门档月费与一次 agent 报错价的客服成本；不对标传统 SEO 套件——排名逻辑与解析逻辑是两个市场。
