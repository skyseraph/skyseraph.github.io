## 🔥 今日趋势

**趋势 1：大厂工具链第二波——从「有没有」卷向「训与管」**
观察：微软 SkillOpt（19,115 星，NeurIPS 2026 Spotlight）把 skill 文档当作冻结 agent 的可训练状态，用 epoch、验证门这套深度学习纪律去训练它；阿里 skill-up（1,488 星）同日更新「评测 + 带证据进化」；讯飞 skillhub（5,435 星）补上企业自托管 skill registry；AMD 官方 skills 目录也在今日推送。继昨日 NVIDIA 的安全与评测、腾讯的交付编排之后，大厂今天的落点从基建存在感转向 skill 全生命周期：训练、评测、进化、私有分发。
代表项目：microsoft/SkillOpt、alibaba/skill-up、iflytek/skillhub

**趋势 2：个人 skill 作品化——工程师的新名片**
观察：Matt Pocock 的个人 skills 集冲到 326,385 星，为今日窗口内全站级热度，README 直言「real engineering, not vibe coding」，配套 6 万订阅的 newsletter 与 skills.sh 分发通道；同日单人作品 ffmpeg-skill（7,497 星）以今日 +367 星仍在 Trending 上升期。skill 正从「团队内部配置」变成可署名、可传播、可职业化的个人技术资产。
代表项目：mattpocock/skills、kajisho5/ffmpeg-skill

**趋势 3：本地化与零依赖成为 skill 的新卖点**
观察：ffmpeg-skill 把「No cloud · No API keys · 纯 Python 标准库」写进标语；同榜 Trending 的 chrome-devtools-mcp（+841 星）同样走本地工具路线。当 skill 生态的安装、评测、治理设施齐备之后，「数据不出机」从合规可选项变成默认需求。
代表项目：kajisho5/ffmpeg-skill

### 1. mattpocock/skills

| 字段 | 内容 |
|------|------|
| 定位 | 「真工程」取向的个人日用 skills 集 |
| Stars | 326385 |
| 语言 | Shell |
| 更新 | 2026-11-17 |

**核心功能**
- Matt Pocock 日常真实工程使用的 agent skills 合集，主张 real engineering 而非 vibe coding
- 与 GSD、BMAD、Spec-Kit 等接管流程的方法论对照：skill 做得小、易改、可组合，控制权留在开发者手里

**亮点**：个人 skill 作品拿到 32.6 万星，为今日窗口内最高热度；skill 第一次像开源框架一样承载个人技术品牌。

**局限**：单一工程师工作流的提炼，跨团队场景需要自行裁剪与验证。

**链接**：https://github.com/mattpocock/skills

### 2. microsoft/SkillOpt

| 字段 | 内容 |
|------|------|
| 定位 | 把 skill 文档当可训练参数的优化器 |
| Stars | 19115 |
| 语言 | Python |
| 更新 | 2026-11-17 |

**核心功能**
- 「像训神经网络一样训 skill」：epoch、batch、文本学习率预算、held-out 验证门，全程不碰模型权重
- 优化器模型把打分 rollout 转成对 skill 文档的 add/delete/replace 有界编辑，只有严格提升验证分才接受
- v0.2.0 的 SkillOpt-Sleep 夜间离线自进化：harvest → mine → replay → consolidate；附带 Claude Code、Codex、Copilot、Devin 的集成壳

**亮点**：NeurIPS 2026 Spotlight + 微软全球 Hackathon 2026 Executive Challenge 第一名，「skill 即可训练参数」成了有论文背书的官方叙事。

**局限**：训练循环本身消耗优化器调用量，部署零成本不等于训练零成本；接受标准依赖验证集质量。

**链接**：https://github.com/microsoft/SkillOpt

### 3. kajisho5/ffmpeg-skill

| 字段 | 内容 |
|------|------|
| 定位 | 给 coding agent 的本地视频编辑器 |
| Stars | 7497 |
| 语言 | Python |
| 更新 | 2026-11-16 |

**核心功能**
- 42 个 FFmpeg 工具带机器可读契约，外加 MCP server，覆盖剪辑、字幕、构图、响度与平台导出
- agent 剪完自检输出：probe → cut → export → check 的闭环
- 无云、无 API key、纯 Python 标准库，`npx ffmpeg-skill` 一键启动；CI 覆盖 FFmpeg 6.1 至 9

**亮点**：今日 +367 星仍处 Trending 上升期，单人作品验证了「本地重型工具 skill 化」的路径。

**局限**：依赖本地 FFmpeg 环境；复杂时间线编辑超出线性工具面的表达范围。

**链接**：https://github.com/kajisho5/ffmpeg-skill
