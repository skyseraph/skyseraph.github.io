## 🔥 今日趋势

**趋势 1：skill 从「教 agent 做事」走向「教 agent 做出好东西」**
观察：今日星数榜前排被「产出质量」类 skill 包揽：taste-skill（120,418 星）给 coding agent 装上艺术指导与浏览器验收门，archify（98,962 星）把想法直接变成可探索的交互页面，huashu-design（30,618 星）一句话产出可交付的网页/App 原型/小程序设计稿。skill 的价值主张正在从「给 agent 加能力」升级为「给 agent 的产出定标准」——真实素材、设计范式、finish gate 验收，工程纪律被搬进了美学领域。
代表项目：Leonxlnx/taste-skill、tt-a1i/archify、alchaincyf/huashu-design

**趋势 2：agent 的已知世界被组织成「可浏览的资产」，而非黑盒向量池**
观察：graphify（152,282 星，今日全站最高）把代码库、文档、PDF 映射成可查询的知识图谱，每条边标注 EXTRACTED/INFERRED，明确宣告「不是向量索引」；火山引擎 OpenViking（42,647 星）用 `viking://` 虚拟文件系统统一 Memory、Knowledge RAG 与 Skills，agent 像浏览目录一样检索自己的上下文。两件事指向同一判断：上下文正在从嵌入黑盒变成可审计、可编辑、可复用的文件系统/图谱资产。
代表项目：Graphify-Labs/graphify、volcengine/OpenViking

**趋势 3：厂商官方 skill 目录成建制入场**
观察：google/skills（24,568 星，今日有推送）以 Google Cloud 方案 recipe 成体系放出；docker/skills、amd/skills、aimlapi/skills 同日活跃；NVIDIA 一边放 SkillSpector（27,367 星）与 SkillEvaluator（4,432 星）组成的扫描评测工具链，一边经营 Verified Skills 管线——扫描、评测、签名后发布官方目录。继上周 ECC 置顶「仅官方渠道安装」警告之后，skill 分发正从社区合集走向「厂商官方 + 安全门禁」的供应链形态。
代表项目：google/skills、NVIDIA/SkillSpector、NVIDIA/SkillEvaluator

## 项目详解（今日榜）

### 1. Graphify-Labs/graphify

| 字段 | 内容 |
|------|------|
| 定位 | 把代码库变成可查询知识图谱的 /graphify skill |
| Stars | 152282 |
| 语言 | Python |
| 更新 | 2026-11-23 |

**核心功能**
- 在 AI coding 助手里输入 `/graphify`，把整个项目（代码、文档、PDF、图片、视频）映射成知识图谱，用查询代替 grep 翻文件
- 代码解析走 tree-sitter AST：确定性、无 LLM、全程本地；文档与多媒体素材用助手自带模型或自配 API key 做语义加工
- 每条边标注 `EXTRACTED`（源码显式存在）或 `INFERRED`（由 graphify 推断），读到的与猜的可以分清
- 明确「不是向量索引」：无嵌入、无向量库，是真图遍历——问一个问题、追两件事之间的路径、解释一个概念
- 本地代码图谱免费；Graphify Cloud 提供常驻图、monorepo/跨仓、形式化验证与 Sentry、Jira 连接器

**亮点**：152k 星为今日 Skill 生态之最，「查询代替 grep」把 agent 的代码理解从文本检索升级为结构化导航；EXTRACTED/INFERRED 的可解释边标注是对 RAG 黑盒的一次直接反叛。

**局限**：代码图谱免费本地，但文档/PDF/图片/视频的语义加工依赖模型或 API key；Cloud 高级能力（跨仓、形式化验证）为闭源商业版。

**链接**：https://github.com/Graphify-Labs/graphify

### 2. Leonxlnx/taste-skill

| 字段 | 内容 |
|------|------|
| 定位 | 让 coding agent 做出 figma/x.ai 级官网的审美 skill |
| Stars | 120418 |
| 语言 | JavaScript |
| 更新 | 2026-11-23 |

**核心功能**
- tasteskill 2.5.1：一条 brief 直接产出专业级公司网站，规则包括平实文案、单一设计系统、每屏一节、左右等边、hero 入场与每页一两个精心设计的记忆点
- 素材全部来真的：真实照片取自 Wikimedia Commons 等开放档案并逐张署名，真实品牌图标与真实产品 UI；shader 与滚动场景严格限定在 tech/gaming/software 页面
- 真实浏览器里的 checker 与 finish gate 强制执行上述规则，不过门不交付
- 安装走 `npx skills add`、Claude Code 插件市场（`taste-skill:` 命名空间防冲突）或 Codex 插件三通道
- Node 22+ 与本机 Chrome/Edge/Chromium 即可运行，不需 API key，自带照片离线可用

**亮点**：把「审美」拆成可执行、可验收的规则集，用浏览器 finish gate 闭环——设计品味第一次被 skill 工程化；12 万星说明「AI 做的官网像模板」这个痛点足够普遍。

**局限**：「figma 级」为项目方自述，无第三方盲测数据；规则化审美对刻意打破常规的品牌方向可能过约束；依赖本机 Chrome 环境。

**链接**：https://github.com/Leonxlnx/taste-skill

### 3. tt-a1i/archify

| 字段 | 内容 |
|------|------|
| 定位 | 把想法、计划或代码库变成可探索的交互 HTML |
| Stars | 98962 |
| 语言 | JavaScript |
| 更新 | 2026-11-23 |

**核心功能**
- 从一句话、一个问题或一份计划出发，产出可探索、可定制、可分享的交互 HTML：旅行行程、学习地图、复杂系统架构皆可
- 「一句话，你的仓库被画出来」：让 agent 读仓库，生成带源码链接、可追路径的架构图
- explainer 模式回答问题：结论先行，再按子问题分面板展开表格、步骤、图表、代码与已校验的图
- 免安装起步：把 `llms.txt` 链接发给 agent 即可自助安装；支持 Cursor、Claude Code、Codex CLI、OpenCode
- 生成后可继续追加指令：「加上鉴权」「高亮缓存未命中路径」「切换浅色主题」

**亮点**：把「图表」从静态产出物变成会话中的活文档——追改、聚焦、换主题都靠一句话；不要求先有仓库，描述即可成图，把 skill 的输入门槛降到零。

**局限**：交互 HTML 的可访问性与嵌入性能未见说明；README 明确第三方在线服务与付费计划由各运营商自担、不代表 Archify 本体，使用托管服务时需自行分辨边界。

**链接**：https://github.com/tt-a1i/archify

### 4. volcengine/OpenViking

| 字段 | 内容 |
|------|------|
| 定位 | 火山引擎开源的 agent 上下文数据库 |
| Stars | 42647 |
| 语言 | Python |
| 更新 | 2026-11-23 |

**核心功能**
- 一个文件系统装下 agent 知道的全部：知识、记忆与技能统一挂载在 `viking://` 虚拟文件系统下
- agent 用 `ls`、`tree`、`read`、`write`、`grep` 浏览上下文，人可以打开任意目录检查、编辑 agent 的所知
- 目录自带生成式摘要：L0 摘要与 L1 概览让 agent 先扫摘要再决定是否读 L2 全文
- 语义检索可限定子目录范围，而非每次扫平面向量池；`find` 直接跑查询，`search` 依会话上下文规划检索
- 会话提交即归档：对话被存档、记忆被抽成可检查可合并的 Markdown；`ov compile` 可把素材编成 wiki、知识图谱或报告
- OpenViking Studio 支持浏览器免装试用，也可自托管 Web Studio

**亮点**：字节系把「上下文」当数据库来做——资源、记忆、技能三类资产同层管理、同套 URI 寻址，直接回应了「agent 记忆是黑盒」的行业痛点。

**局限**：自建数据库带来部署与运维成本；已有向量检索/RAG 管线向 `viking://` 迁移的路径与成本未说明。

**链接**：https://github.com/volcengine/OpenViking
